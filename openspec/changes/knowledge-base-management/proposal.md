## 为什么

Change 2.2–2.4 已提供文档导入、结构切片和向量化服务，但主要依靠 CLI 操作，用户无法在页面中检查资料、处理进度与失败原因。Change 2.5 将这些能力接入可操作的知识库管理界面，为后续检索评估提供可见的数据基础。

## 变更内容

- 增加知识库列表、私有知识库创建、文档列表与详情页，提供分类、来源类型、处理状态和文档版本过滤。
- 支持浏览器上传 PDF、DOCX、DOC、HTML 和 TXT；保存不可变原件，显示去重结果与解析进度。
- 提供规范化正文、章节/页码、切片集版本、切片质量提示和当前模型索引覆盖情况预览。
- 提供重新解析、重新切片、补齐当前模型向量和删除文档操作，明确权限、重复提交、并发和失败恢复行为。
- 采用数据库持久化处理任务与独立 worker，避免 OCR、转换及向量化占用页面请求；页面轮询任务状态。
- 普通用户只管理自己的私有知识库，系统知识库在网页端只读。

## 能力

### 新增能力

- `knowledge-base-management`：知识库与文档管理页面、授权 API、安全上传、内容预览、处理任务生命周期和文档删除。

### 修改能力

无。保留现有 CLI 与基础数据契约；网页端增加更严格的写入边界，内部服务重构保持原调用兼容。

## 影响

- 页面：新增 `/knowledge-bases`、知识库文档列表和文档详情路由，在聊天侧栏增加入口。
- API 与服务：新增 `/api/knowledge-bases/**`，复用会话校验、统一响应、解析、切片和 Embedding 服务。
- 数据：预计增加原件存储定位字段与通用文档处理任务表，使用增量 Prisma migration，不重置数据库。
- 环境：继续使用 PostgreSQL 与本地持久化目录；新增 worker 启动命令及上传/存储配置，不引入 Redis 或外部队列。OCR、LibreOffice 和 Embedding 仍沿用现有配置，缺失时展示对应阶段错误。
- 范围：本阶段不包含云端部署、管理员体系、混合检索、重排序、检索评测或聊天延迟优化；相关性能与检索调试属于 Change 2.6。
