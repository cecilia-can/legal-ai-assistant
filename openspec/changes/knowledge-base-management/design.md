## 背景

现有 Next.js 16 App Router 应用只有聊天入口，使用 Auth.js、Prisma 7、PostgreSQL/pgvector。导入服务接收服务器文件路径，切片服务支持版本与质量校验，Embedding 服务已有任务记录；这些服务尚未形成网页管理流程。OCR 最长可能执行十五分钟，不能直接依赖 HTTP 请求生命周期。

## 目标与范围

交付可登录访问的知识库列表、文档列表和文档详情，支持上传、过滤、预览、重新处理和删除。页面复用现有设计变量、按钮、空态、错误提示、确认对话框和响应式布局。

检索调试、自动调参、混合检索、重排序、聊天延迟优化、云端部署、管理员后台与知识库删除不纳入本次交付。上传后只自动解析，切片与向量化通过明确按钮触发，用户能观察每个阶段。

## 设计决策

### 1. 页面与数据接口

- `/knowledge-bases`：列出当前用户私有库和可读系统库，支持创建私有库。
- `/knowledge-bases/[knowledgeBaseId]`：分页文档列表、上传、分类/来源类型/解析状态/文档版本筛选。
- `/knowledge-bases/[knowledgeBaseId]/documents/[documentId]`：概览、规范化正文、切片集与任务记录，显示各阶段独立状态。
- API 对应 `/api/knowledge-bases`、`/[knowledgeBaseId]/documents`、`/documents/[documentId]`、`/normalized`、`/chunks`、`/tasks`；服务端始终校验文档与 URL 知识库的关系。
- 列表默认每页 20、最大 100，按更新时间与 ID 稳定排序；切片和规范化页分页读取，不把全部正文或向量随列表返回。过滤放在服务端执行，切换筛选回到第一页。
- 返回数据沿用统一 API envelope。401 引导登录，403 表示可读系统库不可写，404 合并不存在与无权读取，409 表示任务冲突，413 表示上传过大。

### 2. 网页权限独立于 CLI 的宽松管理入口

网页读操作允许系统库和当前用户私有库；创建仅允许私有库，ownerId 从 session 设置。上传、重处理、删除仅允许私有库 owner。客户端不能设置 owner、系统 scope、存储路径、任意任务参数或其他用户身份。保留现有 CLI 兼容性，新增统一网页管理 service 授权入口，worker 执行前重新检查归属。

### 3. 上传与原件存储

浏览器通过 multipart 上传单个 PDF、DOCX、DOC、HTML 或 TXT，默认文件上限 20 MiB。使用服务端生成的存储键，在 `DOCUMENT_UPLOAD_ROOT`（默认 `data/document-originals`）下独占创建原件，保留展示文件名，禁止使用客户端文件名拼接路径。扩展名、格式特征和实际大小须校验；对解压与解析产物设置资源限制，不执行 HTML 脚本，不访问 HTML 引用的远程资源。

新增可空 `Document.originalFileUri`，只记录受控根目录相对路径，不向浏览器返回服务器绝对路径。已有 CLI 文档该字段为空时仍可预览；重新解析明确提示需重新上传，网页不读取 sourceUri 指向的任意本地路径或远程 URL。

上传的稳定来源标识默认由知识库内规范化展示文件名产生。同标识同哈希返回现有文档；同标识不同哈希形成新版本，并以事务/冲突恢复保证并发不会重复建版本。文件落盘后将文档注册和解析任务创建放在同一数据库事务；失败的临时文件按受控存储键清理，不删除外部原件。

选择浏览器上传，而不直接暴露现有 CLI 文件路径参数，因为用户文件通常不在服务器上，且后者会扩大服务器文件读取范围。

### 4. 使用数据库任务和独立 worker

新增 `DocumentProcessingTask`：documentId、requestedByUserId、action（parse/chunk/embed）、status（pending/running/succeeded/failed）、阶段、进度、错误、attempts、leaseToken、leaseExpiresAt 和时间戳；可以关联既有 EmbeddingTask ID 作为内部结果，不在网页暴露堆栈和凭证。

同一文档最多一个 pending/running 管理任务，依赖 PostgreSQL 部分唯一索引实现。任务创建返回 202；重复请求返回既有同操作任务，不同操作返回 409。独立命令 `npm run knowledge:worker` 在长驻进程中顺序领取数据库任务，支持 `--once` 调试，不引入 Redis。通过原子领取、心跳租约、有限次数恢复处理进程退出；只有持有当前租约的执行者能提交结果，避免过期 worker 覆盖新结果。

worker 复用解析、切片和向量化服务。解析入口需拆分“注册文档”和“处理已注册文档”，避免 pending 文档被现有去重逻辑直接跳过；CLI 原入口作为组合调用保留。切片沿用事务激活；向量化沿用模型/维度/内容哈希幂等策略。外部副作用均按任务/产物版本隔离，租约失效时停止子进程或放弃提交。

页面有活动任务时每 2 秒轮询，离开页面停止，终态刷新文档与切片；worker 未启动时如实显示排队并提示启动命令，不伪造进度。任务失败显示所属阶段与可操作原因，不自动无限重试。

选择持久化 worker，因为同步请求会与长 OCR 冲突；请求结束后启动未受管理的 Promise 无法保证重启恢复。

### 5. 分阶段状态和数据一致性

解析状态来自 Document；切片状态来自切片集及质量结果；索引状态按当前活动切片集、内容哈希、配置模型/维度统计有效向量数量，显示“未切片/未索引/部分完成/已完成”和模型信息，不能仅使用最近任务是否完成来推断可检索。

重新解析以新派生产物暂存成功后发布。若规范化内容哈希变化，旧切片集保留为历史且不再作为当前活动集，待重新切片；失败保留上一个可用产物，并单独显示此次任务错误。不得在失败或未完成时混合旧切片和新规范化内容。手动重新切片默认策略不变时明确提示复用结果，不声称重新生成；重新嵌入表示补齐当前模型缺失/失败向量，不重新收费生成已存在有效向量。

切片预览允许读取失败/待复核的历史集及质量提示，不能只调用当前仅支持合格文档的 CLI 预览入口。规范化 HTML 作为文本/结构呈现，不使用未经净化的 innerHTML。数据库中的任何产物 URI 都须进行根目录、realpath 和符号链接边界检查，缺失时显示错误而非回退任意路径。

### 6. 删除语义

删除前展示影响并确认。只允许删除当前用户私有文档，无活动任务时在事务内删除对应管理任务、文档级 EmbeddingTask 记录及文档（其切片、向量由已有级联关系清除），保留知识库级任务的汇总记录。活动任务期间返回 409，避免 worker 复写或生成孤立引用。

本阶段删除指移除数据库文档及检索数据，原件与派生文件作为保留副本暂不自动清除；确认框明确说明文件保留，后续单独增加存储回收。不得删除 CLI 引用的外部原文件。选择该策略是因为当前缺少可靠的跨数据库/文件系统事务与回收机制。

## 风险与取舍

- OCR/旧 DOC 依赖缺失 → 按阶段展示错误及安装提示，TXT 可用于无需额外系统软件的验收。
- 本地存储与 worker 部署耦合 → 明确同一持久化目录，默认单应用/单 worker；多机共享存储留后续。
- 上传体积校验发生在应用接收过程中 → 入口层限制请求总大小，应用按实际字节再次校验；部署说明同时给出代理限制，不只信任 Content-Length。
- 文档和解析内容较大 → 分页、按页读取、轮询仅返回状态摘要；worker 使用受限输入与执行超时。
- 原件与派生文件保留占空间 → 明确删除语义、记录存储键；此阶段不提供物理擦除承诺。
- 任务恢复涉及多服务写入 → 任务租约与提交校验覆盖产物发布及切片激活；通过中断恢复和并发测试验证。

## 迁移、验证与回退

1. 实现前阅读已安装 Next.js 的路由、文件上传相关接口和后台执行限制文档。
2. 备份数据库后运行增量 migration、Prisma generate；旧 Document 原件字段允许空值，不回填猜测路径。
3. 配置上传目录、可选上传上限 `DOCUMENT_UPLOAD_MAX_BYTES`，启动应用及 worker。沿用既有解析和 Embedding 凭证，不新增外部账号。
4. 用两个用户及一份短 TXT 验收上传→解析→预览→切片→索引（真实索引需已有服务凭证），验证越权、重复上传、重试与删除。自动测试通过依赖替身避免调用收费模型，真实验证结果单独记录。
5. 运行相关测试、lint、build 和桌面/移动端视觉验收，文档说明 worker 停止时的排队行为。
6. 回退时停止 worker 和应用、恢复旧应用版本，保留增量表和文件；不自动执行破坏性 down migration。现有 CLI 调用维持兼容。

## 待确认事项

无阻塞设计问题。默认采用单文件上传、20 MiB 上限、单 worker、系统库只读和文件保留删除策略；这些行为在实现前随本设计一并交由用户审阅。
