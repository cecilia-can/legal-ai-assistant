## Why

当前聊天流程会把完整会话历史读入后，在输入预算不足时直接从最早消息开始裁剪。法律咨询中早期的当事人陈述、时间线、证据与纠正信息可能正是后续结论的关键，因此需要用可追溯的长期记忆代替简单滑动窗口。

## What Changes

- 为每个会话新增服务端持久化的结构化记忆：通用主题、已有结论、待解问题，以及可选案件事实块。
- 以“旧记忆 + 即将退出近期原文区的消息”为输入，通过独立模型调用生成增量摘要，并对输出进行结构校验、版本化与来源追踪。
- 聊天上下文改为：固定规则、会话记忆、近期原文、按需找回的旧消息与授权知识库 RAG；不再默认将完整历史作为模型输入。
- 为较早会话内容建立受会话与用户权限约束的语义回溯能力，以便在摘要未覆盖某一细节时按当前问题找回少量原文。
- 让应用级输出 token 预算同时约束上游模型调用，并记录记忆压缩与回溯的用量和失败状态。

## Capabilities

### New Capabilities
- `conversation-memory`: 会话级结构化记忆、增量压缩、校验、版本与来源管理。
- `conversation-memory-recall`: 从当前用户有权访问的较早会话内容中按相关性找回少量原文。

### Modified Capabilities
- `chat-api`: 聊天请求的服务端上下文来源改为记忆、近期原文、按需回溯与知识库资料的组合。
- `ai-client`: 上游模型调用必须执行应用配置的最大输出 token 限制，并支持独立的摘要调用。
- `data-persistence`: 在保留不可变原始消息的前提下，持久化会话记忆、来源范围与回溯索引数据。

## Impact

- 受影响代码：`prisma/schema.prisma`、迁移、`lib/ai/context.ts`、`lib/ai/client.ts`、`app/api/chat/route.ts`、消息服务与新增记忆/回溯服务。
- 受影响系统：PostgreSQL/pgvector、DeepSeek/OpenAI-compatible API、每用户 token 配额与日志。
- 不修改客户端聊天 API 请求格式；记忆和回溯均由服务端基于会话归属处理。
