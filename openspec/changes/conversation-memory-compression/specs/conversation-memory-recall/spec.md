## ADDED Requirements

### Requirement: 会话历史回溯索引
系统 SHALL 为较早会话消息创建独立的语义回溯片段与向量索引，且不得复用知识库 `DocumentChunk` 作为会话记忆索引。

每个回溯片段 MUST 记录 `conversationId`、连续的起止消息范围、文本、内容哈希、embedding 模型、维度和创建时间。

#### Scenario: 为早期消息创建可追溯片段
- **WHEN** 系统为不在近期原文区的连续消息建立回溯索引
- **THEN** 每个片段可追溯到其会话和起止消息 ID，且保存所用 embedding 模型和维度

### Requirement: 按会话与用户权限回溯
系统 SHALL 仅从当前请求用户拥有的当前会话中检索回溯片段，并以当前用户问题作为检索 query。

回溯结果 MUST 与知识库 RAG 结果分开标识；回溯内容 MUST 被标记为会话历史原文，不得作为法律资料来源或伪造为知识库引用。

#### Scenario: 相关旧细节被找回
- **WHEN** 当前用户追问同一会话中较早且未出现在近期原文的细节
- **THEN** 系统最多选取配置数量的相关历史片段加入模型上下文，并标记其会话历史来源

#### Scenario: 禁止跨用户或跨会话找回
- **WHEN** 用户请求的会话不归其所有，或检索候选属于另一会话
- **THEN** 系统不返回任何该候选片段，也不将其加入模型上下文

### Requirement: 回溯功能渐进启用
系统 SHALL 将会话历史回溯置于服务端特性开关之后。功能关闭、索引不可用或检索失败时，系统 MUST 继续使用有效会话记忆与近期原文完成聊天，而不是向客户端暴露内部索引错误。

#### Scenario: 回溯索引不可用
- **WHEN** 回溯特性关闭或索引服务暂时不可用
- **THEN** 聊天请求不因回溯失败而中断，并记录服务端可诊断日志
