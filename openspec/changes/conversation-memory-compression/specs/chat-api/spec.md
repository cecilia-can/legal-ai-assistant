## ADDED Requirements

### Requirement: 服务端分层聊天上下文
`POST /api/chat` SHALL 在服务端基于已认证用户和 `conversationId` 组装模型上下文，而不是信任客户端提供的完整历史消息。

上下文 MUST 按预算组合固定系统规则、授权知识库 RAG、有效会话记忆、已授权的回溯历史、近期原文和最新用户消息。系统 MUST 始终保留最新用户消息，且不得将内部摘要、回溯片段或压缩任务信息作为 SSE 事件发送给客户端。

#### Scenario: 长会话使用记忆与近期原文
- **WHEN** 已有有效会话记忆的用户在长会话中发送新消息
- **THEN** 模型输入包含有效记忆和近期原文，而不是默认包含所有历史消息

#### Scenario: 无记忆的短会话保持可用
- **WHEN** 新会话尚未生成会话记忆
- **THEN** 系统使用可容纳的原始历史、固定规则和授权 RAG 正常生成 SSE 回答

### Requirement: 预算优先级与可观测性
聊天 API SHALL 依据应用输入预算计算分层上下文总 token，并按固定优先级收缩低优先级内容。

系统 MUST 记录本次上下文中记忆、近期原文、回溯历史和知识库 RAG 的 token 估算；当低优先级内容被省略时，MUST 在服务端记录原因，不得向用户返回内部细节。

#### Scenario: 上下文超过应用输入预算
- **WHEN** 分层上下文估算超过应用输入预算
- **THEN** 系统优先省略回溯历史与低优先级旧原文，保留最新用户消息、固定规则和有效会话记忆
