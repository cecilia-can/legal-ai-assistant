# 消息流虚拟滚动与 Agent UI 预留

## 为什么

当前 `MessageList` 使用 `messages.map(...)` 一次性渲染全部消息。普通多轮聊天消息量较小时问题不明显，但后续 Agent 会引入工具调用、工具结果、执行状态、中间结果和长日志；Markdown 渲染与代码高亮也会增加单条消息的渲染成本。若继续把所有内容作为普通消息气泡一次性挂载，长会话容易出现首屏慢、滚动卡顿和流式更新时重复布局计算。

本 Change 在 Phase 1 提前建立消息流的虚拟化基础，使后续 Phase 4 Agent 可以复用同一套时间线容器，而不把 Agent 执行过程全部塞进普通消息气泡。

## 变更内容

- 为 `MessageList` 增加支持动态高度的虚拟列表渲染。
- 保留现有流式输出、自动滚动和「回到底部」行为。
- 支持加载更早历史消息时保持当前视口位置。
- 对超长日志、JSON 和代码结果提供折叠或懒加载展示。
- 为未来的工具调用、工具结果和执行状态预留时间线消息项扩展点。
- 左侧 `ConversationList` 继续使用普通滚动，不在本 Change 中虚拟化。

## 能力范围

### 新增能力

- `message-virtualization`：消息流虚拟渲染、动态高度测量、长内容展示策略。
- `agent-timeline-ui`：工具调用和执行状态消息项的 UI 扩展接口，不实现 Agent 执行逻辑。

### 修改能力

- `chat-components`：`MessageList` 的渲染、滚动和历史加载行为。
- `chat-state`：必要时增加消息时间线项或历史分页的前端适配类型。

## 影响范围

- 影响代码：`components/chat/MessageList.tsx`、消息气泡/消息内容组件、消息类型定义及必要的历史加载适配。
- 可能新增一个支持动态高度的虚拟列表依赖；实际依赖需在实现前验证 React 19 与 Next.js 16 兼容性。
- 不修改 Prisma Schema、API 鉴权、Agent 执行引擎或具体法律分析工具。
- 不改变现有消息持久化格式；Agent 专用事件持久化留给 Phase 4/5 的专门 Change。

## 目标 / 非目标

**目标：**

- 长消息列表只渲染可视区域及少量 overscan 项。
- 正确处理 Markdown、代码块和工具结果导致的动态高度。
- 流式追加内容时保持稳定滚动，并避免每个 token 触发无意义的全量重渲染。
- 向上加载历史消息时不改变用户当前阅读位置。
- 为未来 Agent 时间线提供可折叠、可懒加载的展示边界。

**非目标：**

- 不对左侧会话列表做虚拟滚动。
- 不实现 Agent、工具注册、ReAct、Planning 或网络搜索。
- 不在本 Change 中新增工具调用 API 或数据库事件表。
- 不改变当前消息的 Markdown 语义、删除、复制和重新生成行为。

## 预期结果

完成后，普通短会话的交互行为应与当前一致；长消息会话只挂载视口附近的消息，滚动、流式回复和历史加载不会出现明显跳动。后续 Agent 可以将工具调用和执行状态作为时间线项接入，而无需重新设计消息容器。
