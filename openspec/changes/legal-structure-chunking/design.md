## 背景

Change 2.2 的 `document-ingestion` 已把 PDF、DOCX、DOC、HTML 和 TXT 转换为带页码、文本区块及来源定位的版本化规范化产物。`DocumentChunk` 数据模型也已预留文档关系、顺序、文本、定位元数据与策略版本；但尚无服务把这些输入转换为法律语义边界完整的切片。

本设计面向后续 Embedding、检索和 RAG 的输入质量。它必须保持租户边界与来源追踪，且不得修改原始文件或规范化产物。首个版本由服务与验证脚本调用，不引入上传界面、后台队列或外部 AI 服务。

## 目标 / 非目标

**目标：**

- 从规范化文档提取法规、案例、合同模板的可识别结构。
- 按结构优先、长度兜底生成稳定顺序且可追溯的 `DocumentChunk`。
- 在写入前、后发现空内容、乱码、重复页眉页脚与异常截断，并保留可复核结果。
- 以策略版本区分重切片产生的切片集，避免混淆旧数据。

**非目标：**

- 不生成 Embedding、向量索引、检索、重排序或 RAG 回答。
- 不承诺对扫描件、复杂表格、非标准版式或所有法律文书实现无误语义识别。
- 不修改原始文件、OCR 产物或规范化 JSON。
- 不实现管理界面、人工审核工作流和异步任务队列。

## 决策

### 1. 以版本化规范化产物作为唯一切片输入

切片服务读取 `Document.normalizedUri` 指向的 `NormalizedDocument`，而非重新解析原始文件。输入在读取时校验 schema 版本、文档状态和内容可用性；不满足条件时返回可操作错误。

选择此方案是因为它继承 Change 2.2 的格式适配、OCR 和来源信息，避免不同下游重新解析后产生页码或正文不一致。替代方案是直接从 `Document` 或原始文件切片，但会重复解析逻辑并破坏可重复性。

### 2. 使用“类型分类 + 规则识别 + 长度兜底”的分层策略

先根据文档 category、来源类型与文本特征选择法规、案例、合同或通用策略；各策略用确定性标题、编号和关键词规则形成候选结构树。生成切片时优先保留完整结构单元；仅当单元超过配置的 token/字符上限时，在段落或句子边界拆分，并在每个子切片保留同一父级定位和分片序号。

规则优先可保证可解释、可测试、离线运行且适配法律编号形式。替代的仅固定长度切分会破坏条款语义；依赖 LLM 的结构识别会增加成本、隐私边界与不确定性，因此不纳入本 Change。

### 3. 以切片集版本实现可重放与安全替换

每次执行生成一个由 `documentId`、规范化内容哈希与 `chunkingStrategyVersion` 标识的切片集。对相同输入与策略的重复执行必须幂等；策略或内容变化时创建可区分的新切片集。写入采用事务：成功后再激活当前集，失败时保留此前可用集。

这避免重切片过程中出现部分新旧切片混合。替代的原地删除再插入实现简单但在失败或并发时会短暂失去可用数据。

### 4. 质量校验是独立、可组合的管线步骤

质量校验在结构识别后、持久化前运行，并可在已保存切片上重复执行。检查器输出机器可读的 issue（类型、严重级别、定位、说明）；严重问题阻止该切片集成为当前集，非严重问题会随切片或切片集元数据保存以供后续界面展示。

独立检查器能随着真实样本迭代阈值，无需耦合每个切片策略。替代的仅依赖导入阶段校验无法发现因切分造成的截断或空块。

### 5. 定位元数据统一采用可扩展结构

每个切片保留页码范围、原文 block/字符范围，以及可选的 chapter、section、article、paragraph、item、clause、casePart 等字段。正文和稳定 ordinal 保持在 `DocumentChunk` 的一等字段；扩展定位与质量信息写入结构化 JSON 元数据，避免为每种文书类型频繁改变表结构。

这在当前模型兼容性与查询灵活性间取得平衡。高频筛选字段若在后续检索评估证明需要索引，再迁移为明确列。

## 风险 / 取舍

- [非标准法律编号或 OCR 噪声导致结构误判] → 保留原文定位、置信度/质量 issue，并使用通用策略兜底。
- [超长条款仍需拆分，影响完整性] → 只在段落、句子等弱边界拆分，记录父级结构与分片序号。
- [重复页眉页脚被当作正文] → 以跨页重复频率检测，在生成正文前标记或剔除，并把处理结果写入 issue。
- [重切片任务失败或并发] → 使用版本化切片集与事务激活，旧集在新集完成前保持可用。
- [字符长度与模型 token 数不完全一致] → 统一由可替换的长度估算器计算；首版选用保守阈值，Change 2.4 再结合实际 Embedding 模型校准。

## 迁移计划

1. 为承载策略版本、定位、内容哈希、质量状态及当前切片集补充必要的数据迁移或等价持久化结构。
2. 发布切片服务和验证脚本；未切片或不合格文档不进入后续向量化流程。
3. 使用规范化测试样本运行切片与质量校验，确认来源定位及幂等性。
4. 若新策略出现问题，停止激活新切片集并继续使用上一个可用集；无需回写或删除原始文件与规范化产物。

## 开放问题

- 各类型文书的首版最大 token/字符阈值及重叠范围，需在真实样本评估后确定。
- `DocumentChunk` 现有字段与切片集版本、质量 issue 的最终 Prisma 映射，应在实现前结合当前 schema 选择独立模型或 JSON 元数据。
- 是否在 Change 2.5 的管理界面中允许人工更正结构标签，留待界面需求明确后决定。
