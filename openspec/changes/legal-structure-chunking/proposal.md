## 为什么

Change 2.2 已将多格式法律文件转换为带页码与来源信息的规范化文档，但系统尚不能按法律文本的语义结构生成可检索、可引用的切片。若直接按固定字符数分割，会割裂法条、合同条款和案例论证，降低后续 Embedding、检索与 RAG 回答的可靠性。

本 Change 在规范化产物可用后建立结构化切片与质量校验能力，为 Change 2.4 的向量化与可追溯回答提供可信输入。

## 变更内容

- 新增面向法律法规、司法解释、案例与合同模板的结构识别和切片流程。
- 采用“结构优先、长度兜底”的策略：优先保留章、节、条、款、项、案例段落和合同条款边界；结构单元过长时再以可追溯方式拆分。
- 将每个切片的文档、页码、章节、条款编号、原文位置、顺序、内容哈希与策略版本持久化。
- 新增切片质量校验，识别空内容、乱码、重复页眉页脚和异常截断，并输出可人工复核的结果。
- 支持按新策略版本重新切片，保留既有切片集的可追溯性。

## 能力

### 新增能力

- `legal-structure-chunking`：从规范化法律文档识别文本结构、生成可追溯切片，并校验切片质量。

### 修改能力

- 无。

## 影响

- 受影响代码：新增文档结构识别、切片策略、质量校验与持久化服务，以及相应测试与验证脚本。
- 受影响数据：复用 `Document` 与 `DocumentChunk` 关系；为落地现有切片数据契约，可能补充切片定位、内容哈希、策略版本和质量状态的等价字段或 JSON 元数据。
- 受影响输入：仅读取 Change 2.2 生成的版本化规范化文档；原始文件及规范化产物保持不变。
- 外部依赖：不新增云服务、环境变量或 API Key；不生成 Embedding，不创建向量索引。
