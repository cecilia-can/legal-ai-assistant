## Why

当前聊天链路由浏览器在流式回复结束后再保存 user 与 assistant 消息。页面刷新、网络中断、重复提交或同一会话并发发送时，可能丢失消息、产生重复记录，或使回复与实际上下文顺序不一致。

需要将一次 AI 回复作为可持久化、可追踪的服务端生成任务，使流式对话在取消、超时和异常情况下仍能保持数据一致性，并为后续多实例部署提供正确的并发控制基础。

## What Changes

- 服务端在调用模型前，以事务创建用户消息、助手占位消息和生成任务记录。
- 新增生成任务状态，区分生成中、完成、已取消和失败，并记录可安全展示的失败原因。
- 为每轮聊天请求引入客户端请求 ID，并通过数据库唯一约束实现幂等创建。
- 限制同一会话同时只能存在一个进行中的生成任务；不同会话仍可并行生成。
- 将流式完成、取消、超时和异常统一映射为可持久化的终态，只有收到 `done` 才视为完成。
- 调整重新生成流程：新回复成功前保留旧回复，避免生成失败导致历史丢失。

## Capabilities

### New Capabilities

- `chat-generation-lifecycle`: 服务端持久化管理 AI 生成任务、状态转换、取消与失败恢复。
- `chat-request-idempotency`: 以会话和客户端请求 ID 为边界，确保聊天请求重复送达不会重复创建记录或调用模型。
- `conversation-generation-concurrency`: 保障同一会话的生成任务串行执行，并定义并发请求的响应行为。

### Modified Capabilities

- `data-persistence`: 将消息持久化从前端流结束后的批量写入，改为服务端创建并更新生成任务关联消息。
- `chat-api`: 聊天接口接受请求 ID，返回并更新生成任务状态，处理取消、超时和流式终态。
- `sse-protocol`: 将 `done` 定义为唯一成功终态，并定义取消、超时和异常的结构化事件语义。

## Impact

- 影响 Prisma Schema 和迁移：新增生成任务模型、外键、状态字段、唯一约束与查询索引。
- 影响 `app/api/chat/route.ts`、消息服务、AI 客户端、SSE 工具及前端聊天状态管理。
- 需要新增 API、服务层和状态转换测试；不引入 Redis 或消息队列，本 Change 不覆盖跨实例全局限流。
