## 背景

系统已有 PostgreSQL pgvector 扩展、`Embedding` 模型及 `DocumentChunk` 与 `DocumentChunkSet` 的版本化关系。切片仅在其所属切片集通过质量检查并已激活后才是可供检索的候选。`KnowledgeBase` 是文档可见性边界，用户私有知识库必须始终按已认证用户授权；系统知识库的访问策略同样必须在服务端决定。

本 Change 需要把这些持久化基础转化为可重放的向量化任务与可追溯的 RAG 回答，同时避免把客户端内容、知识库权限或历史消息当作可信输入。

## 目标 / 非目标

**目标：**

- 以固定、显式的模型和维度配置生成并保存切片 Embedding。
- 让重复任务幂等、可恢复，并保留可操作的失败状态。
- 只检索已激活、质量可用且调用者获准访问的切片。
- 为每个检索结果保留分数及文档标题、页码、结构定位等引用信息。
- 将服务端检索到的有限上下文加入聊天模型调用，并在证据不足时约束回答语气。

**非目标：**

- 不实现上传、知识库管理 UI、后台分布式队列或人工审核界面。
- 不实现关键词混合检索、重排序、自动评测或跨知识库全局搜索优化。
- 不在本 Change 调整结构切片策略、原始文件或规范化产物。
- 不把向量或来源文本暴露为可由浏览器提交后直接信任的参数。

## 决策

### 1. Embedding 以内容哈希、模型和维度作为可重放身份

服务读取一个已激活且合格的切片集，为每个切片以其 `contentHash`、模型标识和已验证维度生成向量。已有相同 `(chunkId, model, contentHash)` 记录时复用而不重复调用模型；内容或模型变化时创建新的记录。调用模型返回的维度必须与配置及数据库元数据一致，否则该批次失败且不写入不一致向量。

这延续现有唯一约束，避免无意义的 API 成本和模型混用。模型与维度固定为环境配置，而不是由请求方传入。

### 2. 任务按批次记录进度并以可恢复失败结束

向量化入口一次处理受限的切片批次，保存待处理、处理中、成功、失败或部分完成等状态，以及已完成数量、失败原因和重试次数。暂时性模型或网络错误按照有限退避重试；达到上限时保留失败记录，使后续运行可以只处理缺失或失败项。

首版选择可重复执行的服务/CLI 入口，不引入外部队列。任务状态可作为后续管理界面的数据来源。

### 3. 检索过滤先于相似度排序，并使用参数化向量 SQL

检索服务先在服务端解析身份及可访问的知识库范围，再限制为已激活、质量可用、拥有目标模型与维度的 Embedding。可选分类和显式知识库过滤只能进一步收窄这个集合。向量距离计算、向量值、数量及过滤条件必须参数化，不能将客户端字符串拼入 SQL。

pgvector 的索引维度与已选模型固定；模型升级使用新的模型标识与索引/迁移路径，避免在一个索引中混合不同维度。返回结果按距离稳定排序，并带回引用展示所需的文档与定位信息。

### 4. RAG 上下文是服务端构造的有界证据包

聊天路由验证会话及用户身份后，使用本轮合法用户问题向量化并调用检索服务。上下文构建器为每段证据分配稳定的来源标签，包含文档标题、页码、条款/章节定位和正文，并设置条数及字符/token 上限。System Prompt 明确要求模型仅在证据支持的范围内回答、引用来源标签，并在没有充分资料时说明不确定性。

客户端只提交本轮消息；其不能提交向量、检索正文、知识库归属或引用标签。检索或 Embedding 不可用时，路由返回可区分的错误或按产品策略明确降级，不得伪造来源。

### 5. 测试以授权边界、版本一致性和可追溯性为核心

单元与集成测试覆盖：重复向量化、内容或模型变化、维度不匹配、重试、失败恢复、仅检索激活切片、租户越权、分类过滤、稳定排序、引用构建、无命中回答和聊天端拒绝客户端伪造来源。数据库相关验证使用隔离测试数据或可替换仓储，不能重置开发数据库。

## 风险 / 取舍

- [Embedding API 失败、限流或成本不可控] → 限制批大小，记录进度与错误，采用有限重试和幂等跳过。
- [模型升级造成向量维度不兼容] → 将模型和维度绑定到配置与记录，按模型隔离索引和查询。
- [向量 SQL 绕过租户边界] → 授权过滤在服务层和查询层同时体现，并自动化测试跨用户读取。
- [检索文本过长挤占聊天上下文] → 对结果数量及每段和总上下文使用可配置上限，保留引用元数据。
- [模型生成未被资料支持的结论] → Prompt 要求基于来源回答或表达不确定性；本 Change 不承诺消除所有幻觉。

## 迁移计划

1. 检查现有 pgvector 扩展及 `Embedding` 表；以版本化迁移加入任务状态或必要索引。
2. 配置受支持的 Embedding 模型、维度和密钥，仅通过环境变量读取。
3. 部署向量化入口后，先针对测试或小范围已激活切片运行，验证维度、计数和来源定位。
4. 启用检索与 RAG 聊天集成；若出现异常，关闭检索增强或使用既有纯聊天路径，保留已有切片和 Embedding 数据供诊断。

## 开放问题

- 首版 Embedding 模型、每批数量、重试次数、Top-K 及上下文 token 预算，在实现前依据供应商限制与实际模型确认。
- 检索不可用时是显式报错还是允许不带来源的通用聊天，需在实现时与现有聊天产品行为统一。
