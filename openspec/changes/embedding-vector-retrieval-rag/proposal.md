## 为什么

Change 2.3 已将可用的规范化法律文档转换为带结构定位和质量结果的版本化切片，但这些切片尚不能按语义相似度被检索，也不会被安全地用于聊天回答。缺少向量化和来源约束的检索层时，模型无法稳定引用用户获准访问的资料，回答也无法说明依据。

本 Change 在已有 pgvector、知识库归属、文档导入和结构切片基础上，建立可重试的 Embedding 流程、租户安全的向量检索，以及带来源的 RAG 上下文组装。

## 变更内容

- 新增 Embedding 模型配置、批量处理、幂等写入、失败重试和可查询的任务状态。
- 为可用切片写入 pgvector 向量，并建立与模型维度匹配的相似度检索索引。
- 新增按调用者授权范围、知识库、文档分类和结果数量过滤的检索服务；结果保留文档、页码与结构定位。
- 新增 RAG 上下文构建器，将受限检索结果以明确来源标识传递给聊天模型，并在无可靠结果时要求回答表达不确定性。
- 将检索增强接入现有聊天流程，不信任客户端传入的检索内容或来源。

## 能力

### 新增能力

- `embedding-retrieval-rag`：对已通过质量检查的法律文档切片生成向量，在授权边界内检索可引用来源，并为聊天提供受控 RAG 上下文。

### 修改能力

- `chat-api`：聊天请求在需要知识库增强时从服务端检索并组装上下文，不接受客户端伪造的资料内容或来源。

## 影响

- 受影响代码：Embedding 客户端与任务服务、向量 SQL/索引、检索与 RAG 上下文服务、聊天路由及其测试和验证脚本。
- 受影响数据：复用 `Embedding`、`DocumentChunk`、`DocumentChunkSet` 和 `KnowledgeBase`；可能增加任务状态持久化和数据库迁移。
- 环境配置：需要 Embedding 模型标识及其 API 凭证；不得将密钥写入仓库。
- 不包含：知识库管理界面、混合检索、重排序和检索质量调参。
