# Word / PDF 规范化与切片优化说明

本文记录当前文档处理链路中，针对 Word、PDF 规范化及结构化切片已完成的优化。

## 1. Word 文档规范化

### 1.1 恢复自动编号

- 读取 DOCX 的 `numbering.xml`、段落 `numPr`、编号层级和编号格式。
- 将自动编号与段落正文合并，例如：`第一条 委托代理事项`。
- 支持常见中文编号、阿拉伯数字、字母与项目符号的编号恢复。

### 1.2 保留段落结构元数据

每个规范化 block 可保留：

- 段落类型：标题、正文、列表项、表格等；
- 标题层级：来自 Word 样式或大纲级别；
- 列表 ID、列表层级、编号文本；
- 原始逻辑定位：如 `paragraph:25`、`table:3`；
- 已识别的章节路径和条款编号。

### 1.3 以渲染 PDF 补充物理页码

- DOC/DOCX 本身没有稳定的物理页码，不能依据 XML 伪造页码。
- 使用 LibreOffice 将 Word 文档渲染为 PDF。
- 按文档顺序将规范化段落匹配到渲染 PDF 文本，写入：
  - `sourcePage`：段落起始页；
  - `sourcePageEnd`：跨页段落结束页；
  - `renderedPdfUri`：渲染 PDF 派生产物位置。
- 顶层 `pages[].pageNumber` 按渲染 PDF 的物理页组织。

### 1.4 跨页条款处理

- 跨页条款只保留一次，不复制到后一页。
- 正文归入起始页，同时以 `sourcePage` 至 `sourcePageEnd` 标记完整引用范围。
- 切片保留整项正文和页码范围，不因跨页而丢失或截断条款。

## 2. PDF 文档规范化

### 2.1 从文本项还原阅读顺序

- 不再把整页 PDF 文本直接拼接为一个 block。
- 读取 PDF 文本项的坐标、宽度、高度和字体信息。
- 按纵坐标聚合为视觉行，行内按横坐标恢复阅读顺序。

### 2.2 从视觉行合并为段落

- 以页面实际行距和字高的中位值作为动态基线，不再使用固定阈值。
- 连续换行的正文会合并为同一个段落 block。
- 明显的版面间隔会形成新的段落。
- 页首正文可标记为上一页段落的延续，便于跨页追踪。

### 2.3 页眉、页脚和页码清理

- 统计多页重复出现的页首/页尾文本，识别重复页眉页脚。
- 过滤单独的“第 N 页”页码行。
- 避免重复页眉页脚进入规范化正文和后续向量检索。

### 2.4 通用标题识别

PDF 标题识别不依赖预先穷举标题词，而是综合版面信号计算标题置信度：

- 文本短小且没有常见句末标点；
- 行宽相对较短；
- 上下存在较大留白；
- 居中、字号较大或带编号；
- 排除日期、数字尾行等容易误判的短行。

高置信度文本被规范化为 `heading` block，并记录 `headingConfidence`；未知标题也可参与后续切片。

### 2.5 已知案例栏目语义增强

对常见案例栏目，在通用标题基础上增加可选语义角色：

| 栏目 | 语义角色 |
|---|---|
| 关键词 | `case_keywords` |
| 裁判要旨 / 裁判要点 | `case_holding` |
| 基本案情 | `case_facts` |
| 争议焦点 | `case_issues` |
| 裁判结果 | `case_judgment` |
| 裁判理由 / 法院认为 | `case_reasoning` |
| 关联索引 / 相关法条 | `case_index` |

语义角色用于提升检索、引用和展示质量；它不是识别标题或切片边界的唯一条件。

## 3. 结构化切片优化

### 3.1 通用切片原则

- 先依据规范化后的标题、段落、条款和页码结构切分。
- 完整结构单元优先；仅在超过长度上限时，才按段落或句子进一步拆分。
- 每个切片保留来源页码、block/字符范围、内容哈希和策略版本。

### 3.2 法律法规与司法解释

- 优先识别并按编、章、节、条、款、项切分。
- 条文编号与标题作为结构定位，避免按固定字符数截断法条。

### 3.3 合同与协议

- 优先以条款编号和条款标题作为边界。
- 使用 Word 自动编号恢复后的“第一条”“（一）”等结构信息。
- 未能识别条款编号时，仍可按通用标题和段落进行兜底切分。

### 3.4 典型案例

- 以已识别的案例栏目作为语义边界。
- 同时以所有高置信度的通用标题作为边界，因此未写入案例栏目字典的标题也能独立切分。
- 可将案例摘要、裁判要旨、基本案情、裁判结果、裁判理由和关联索引拆为独立检索单元。

### 3.5 文书类别与策略选择

- 规范化层主要按文件格式执行通用处理。
- 切片层按法规、案例、合同、通用文档选择不同结构策略。
- 已指定的 `Document.category` 优先；未指定时，可基于文本内容进行基础策略推断。
- 规范化产物元数据会记录 `category`，用于检查数据库类别与处理结果是否一致。

## 4. 质量与可追溯性

- 检测空内容、乱码、重复页眉页脚和异常截断。
- 切片集以规范化内容哈希和策略版本区分，支持重新切片。
- 可生成 Markdown 预览，查看正文、页码范围、结构定位和质量提示。

## 5. 重新处理注意事项

- 同一来源和内容哈希的普通导入会返回 `duplicate`，不会更新旧产物。
- 解析器、页码映射或切片规则升级后，应使用 `--reprocess` 重新规范化。
- 规范化内容变化后，应再次执行切片，生成基于新内容哈希的新切片集。
