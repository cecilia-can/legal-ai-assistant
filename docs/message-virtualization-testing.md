# 消息虚拟列表验收说明

## 目标

验证消息列表在长会话中只渲染视口附近内容，并且不破坏既有的流式回复、回到底部与历史分页体验。

## 准备数据

1. 在一个会话中至少准备 60 条消息；为了验证动态高度，其中应包含普通文本、长 Markdown、代码块和表格。
2. 若要验证分页，请准备超过 API 默认单页 50 条的消息。进入会话后，首次仅加载最近 50 条；向上滚动至顶部会自动请求带 `cursor` 的更早页面。
3. 在浏览器开发者工具的 Elements 面板确认：即使内存中已加载很多消息，消息列表中实际挂载的时间线项仅为当前可视消息及前后各 4 条 overscan。

## 验收场景

### 长列表滚动

1. 快速向上、向下滚动长会话。
2. 确认没有持续的白屏、重复消息或消息错位。
3. 确认屏幕外消息节点会被卸载，进入视口时再渲染。

### 动态高度与流式输出

1. 发送一个要求 Markdown、列表和代码块的请求。
2. 停留在列表底部，确认流式文本增长时持续跟随底部。
3. 在流式过程中向上滚动阅读历史，确认视口不会被拉回底部，且出现「回到底部」按钮。
4. 等流式结束、Markdown 与代码高亮完成后，确认最后一条消息没有重叠、裁切或明显跳动。

### 历史分页

1. 将当前会话滚动到顶部。
2. 在 Network 面板确认请求为 `GET /api/conversations/:id/messages?cursor=...`。
3. 确认「正在加载更早消息」出现，响应成功后更早消息插入顶部。
4. 确认加载前正在阅读的第一条可见消息仍处于大致相同的视口位置。
5. 重复直至服务端返回 `nextCursor: null`，确认不再发起请求。

### Agent 时间线扩展点

当前页面不会产生 Agent 事件。接入 Agent 后，传入 `timelineItems` 可验证：

1. `tool-call` 与 `execution-status` 展示名称、摘要与状态。
2. `tool-result` 的超过 1,200 字符详情默认折叠；点击后展开且列表高度自动更新。
3. 普通 `message` 仍保留复制、删除、重新生成和 Markdown 行为。

## 自动化验证

组件测试覆盖虚拟窗口渲染与长工具结果的展开/收起；执行：

```powershell
npm.cmd test
```

代码层静态验证命令：

```powershell
node_modules\.bin\tsc.cmd --noEmit
npm.cmd run lint
```

完整 `npm run build` 需要构建环境能够访问 Google Fonts；网络受限时，`next/font` 获取 Geist 字体失败不代表虚拟列表编译失败。
