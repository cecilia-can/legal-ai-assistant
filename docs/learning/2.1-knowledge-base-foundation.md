### schema.prisma 是手写源文件，Client 与 Migration 才是自动生成

- **来源问题**：`prisma/schema.prisma` 里的代码是不是都是我自己定义写入的？不是自动生成的？
- **结论**：`schema.prisma` 由开发者**手写/维护**，是数据模型的唯一源文件；Prisma 根据它自动生成 **Prisma Client**（本项目输出到 `app/generated/prisma`）和 **Migration SQL**（`prisma/migrations/`）。
- **原理 / 为什么**：Prisma 采用 schema-first 工作流——你先描述「想要什么表结构」，再跑 CLI 把描述同步到数据库并生成类型安全的客户端。反向也有 `prisma db pull`（从已有 DB 反推 schema），但日常开发以手改 schema 为主。
- **易错点 / 坑**：不要把 `app/generated/prisma` 或 `prisma/migrations/*.sql` 当成手改对象；改 schema 后必须跑 `prisma migrate dev`（改 DB + 生成 migration）和/或 `prisma generate`（只重生 Client）。
- **延伸**：
  - 典型命令：`npx prisma migrate dev --name <描述>`、`npx prisma generate`、`npx prisma studio` ✅
  - `prisma db pull` 适合接手遗留数据库；与本项目 schema-first 流程相反 ⚠️需查证
  - 🔗 https://www.prisma.io/docs/orm/prisma-schema/overview
- **标签**：#prisma #schema #migration #codegen
- **状态**：#待复习

### Prisma 字段级属性：@id、@default、@unique、@updatedAt

- **来源问题**：请介绍一下 `@id`、`@default(cuid())` 等语法。
- **结论**：单 `@` 修饰**字段**：`@id` 标主键；`@default(...)` 设插入默认值；`@unique` 唯一约束；`@updatedAt` 在 update 时自动刷新时间；字段类型后的 `?` 表示 nullable。
- **原理 / 为什么**：这些是 Prisma Schema Language (PSL) 的字段属性，迁移时会转成 PostgreSQL 的 PRIMARY KEY、DEFAULT、UNIQUE 等 DDL。`cuid()` 生成碰撞概率极低的字符串 ID，适合分布式/Serverless；`now()` 取插入时刻。
- **易错点 / 坑**：`@updatedAt` 只在 **update** 时触发，不是 insert；`String?` 的 `?` 是类型 nullable，与 `@default` 无关。每个 model 必须有 `@id` 或 `@@id`（复合主键）。
- **延伸**：
  - 常见 ID 策略：`cuid()`、`uuid()`、`autoincrement()`（自增整型，PostgreSQL 用 SERIAL/IDENTITY）✅
  - 本项目 `User`、`Conversation`、`Document` 等统一用 `String @id @default(cuid())` ✅
  - 🔗 https://www.prisma.io/docs/orm/reference/prisma-schema-reference#id
- **标签**：#prisma #schema #primary-key #default
- **状态**：#待复习
- **日期**：2026-08-09

### @db.Text 与 @map：原生类型与列名映射

- **来源问题**：请介绍一下 `@db.Text` 等语法。
- **结论**：`@db.Text` 把 Prisma 的 `String` 映射为 PostgreSQL 的 `TEXT`（无长度上限），适合消息正文、OAuth token、错误信息等长文本；`@map("snake_case")` 让模型字段（camelCase）对应数据库列名（snake_case）。
- **原理 / 为什么**：Prisma 标量类型是跨数据库抽象层；`@db.*` 是 native type attribute，按 provider 映射到具体 SQL 类型。PostgreSQL 下默认 `String` 可能映射为有限长度的 `varchar`，长内容应显式 `@db.Text`。
- **易错点 / 坑**：`Unsupported("vector")` 用于 pgvector 等 Prisma 尚未完整支持的类型——迁移能建列，但 Client 类型支持有限，查询向量字段需 raw SQL 或扩展方案。
- **延伸**：
  - 同类 native type：`@db.VarChar(n)`、`@db.Json`（PostgreSQL 映射 jsonb）✅
  - 模型级 `@map("table_name")` 可改表名；`@@map` 改复合约束名 ✅
  - 🔗 https://www.prisma.io/docs/orm/reference/prisma-schema-reference#model-field-scalar-types
- **标签**：#prisma #postgresql #native-type #mapping
- **状态**：#待复习
- **日期**：2026-08-09

### @relation 一对多关系与 onDelete

- **来源问题**：请介绍一下 `@relation` 语法。
- **结论**：`@relation(fields: [外键字段], references: [对方主键], onDelete: ...)` 定义关系；**存外键的一侧**写 `fields`，**「一」的一侧**只写数组反向字段（如 `User.conversations Conversation[]`）。同一对 model 有多条关系路径时需 `@relation("RelationName")` 命名区分。
- **原理 / 为什么**：Prisma 里一条关系由两个 relation field 表达：scalar 外键 + 导航字段。`onDelete: Cascade` 删父记录时级联删子记录；`SetNull` 删父记录时把可选外键置 null（如 `Document.uploadedBy`）。
- **易错点 / 坑**：`@relation` 只能加在 relation field 上，不能加在纯 scalar 外键列上（scalar 列与 relation field 是成对出现的）。User 同时关联 `KnowledgeBase`（owner）和 `Document`（uploader）必须用不同 relation 名，否则 Prisma 无法消歧。
- **延伸**：
  - `onDelete` 还可选 `Restrict`、`NoAction`、`SetDefault`；审计/支付类子表慎用 Cascade ✅
  - 1:1 关系需在 FK 列加 `@unique`，否则语义上是 1:N ✅
  - 🔗 https://www.prisma.io/docs/orm/prisma-schema/data-model/relations
- **标签**：#prisma #relation #foreign-key #cascade
- **状态**：#待复习
- **日期**：2026-08-09

### @@ 表级属性：复合主键、复合唯一、索引

- **来源问题**：schema 里 `@@id`、`@@unique`、`@@index` 是什么？
- **结论**：双 `@@` 修饰**整个 model**：`@@id([a, b])` 复合主键；`@@unique([a, b, c])` 多列组合唯一；`@@index([a, b])` 建索引加速查询。本项目例：`Account` 用 `@@id([provider, providerAccountId])`；`Document` 用 `@@unique([knowledgeBaseId, sourceIdentifier, contentHash])` 防重复导入。
- **原理 / 为什么**：单字段约束用单 `@`；跨字段约束必须用 `@@`。复合唯一允许各列单独重复，但组合不能重复——适合「同一知识库内同一来源+同一内容哈希只能有一条 Document」这类业务规则。
- **易错点 / 坑**：不要把 `@@unique` 和多个 `@unique` 混淆——前者是组合唯一，后者是每列各自唯一。外键列常配 `@@index` 提升 JOIN/过滤性能。
- **延伸**：
  - Prisma 还支持 `@@fulltext`（MySQL/PostgreSQL 等，视 provider 而定）⚠️需查证
  - Change 2.1 的 `Embedding` 对 `[chunkId, model, contentHash]` 做复合唯一，避免同一 chunk 同一模型重复 embedding ✅
  - 🔗 https://www.prisma.io/docs/orm/reference/prisma-schema-reference#model
- **标签**：#prisma #index #unique #composite-key
- **状态**：#待复习
- **日期**：2026-08-09
