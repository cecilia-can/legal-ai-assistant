### Word 自动编号与结构化段落

- **来源问题**：如何读取并保留 Word 段落的自动编号，恢复“第一条 委托代理事项”，并让切片器使用这些结构？
- **结论**：DOCX 规范化需读取 `numbering.xml` 与段落 `numPr`，将编号文本合并入正文，同时保留编号、列表层级、标题层级和段落类型。
- **原理 / 为什么**：Word 自动编号通常不在段落正文 XML 中，而是由编号定义和段落引用共同决定。只提取 `w:t` 会丢失“第一条”“（一）”等重要法律结构信号；恢复后，合同条款与法律条文识别才能以稳定编号作为边界。
- **易错点 / 坑**：编号文本与正文合并后仍须单独保存列表 ID、层级和原始编号，否则后续无法区分“标题编号”和普通正文中的数字。
- **延伸**：
  - Word 的复杂 restart、编号覆盖和特殊数字格式需要持续以真实模板验证 ⚠️需查证
- **标签**：#word #docx #numbering #normalization
- **状态**：#待复习
- **日期**：2026-09-12

### Word 物理页码以渲染 PDF 为准

- **来源问题**：为什么 Word 规范化文档的 `pageNumber` 是 `null`，以及如何让 PDF 渲染成为页码定位来源？
- **结论**：DOC/DOCX 的 XML 不应伪造物理页码；应渲染为 PDF，再把 Word 段落映射到渲染 PDF 的起止页。
- **原理 / 为什么**：Word 分页由字体、纸张、边距和版式共同决定，逻辑段落本身没有可靠物理页码。规范化后以 `sourcePage`、`sourcePageEnd` 保存段落页码范围，并按渲染 PDF 的物理页组织页面，才能支持可追溯引用。
- **易错点 / 坑**：普通导入遇到相同哈希会返回 `duplicate`，不会重新解析或覆盖旧产物；必须使用 `--reprocess` 才会执行新的渲染和规范化逻辑。
- **延伸**：
  - LibreOffice 的可执行文件路径由项目 `.env` 的 `DOCUMENT_OFFICE_COMMAND` 提供，PowerShell 不会自动读取 `.env` ✅
- **标签**：#word #pdf #page-location #provenance
- **状态**：#待复习
- **日期**：2026-09-12

### 跨页条款的完整性与页码范围

- **来源问题**：条款跨两页时会不会丢失，是否应展示在上一页？
- **结论**：跨页条款正文应只保留一次，归属起始页，并记录从起始页到结束页的页码范围；切片保留完整条款而不截断或重复。
- **原理 / 为什么**：用连续 PDF 文本流匹配 Word 段落可以识别跨页文本，不应要求整个段落存在于单个 PDF 页面。切片引用以 `pageFrom–pageTo` 表示范围，避免将同一条款重复写入多个检索单元。
- **易错点 / 坑**：若只在单页查找完整段落，跨页段落会失去页码或被放到无页码区，继而破坏源文顺序。
- **延伸**：
  - 未来可在预览界面显示“本段续至第 N 页”，提升人工核验体验 ⚠️需查证
- **标签**：#pdf #cross-page #chunking #citation
- **状态**：#待复习
- **日期**：2026-09-12

### 规范化与切片的职责分离

- **来源问题**：为何要在 PDF 解析器中处理行和段落，而不是只在切片时按“基本案情”“裁判结果”等关键词切？
- **结论**：规范化负责恢复通用版面结构和来源定位；切片负责按文书类别解释这些结构并组合检索单元。
- **原理 / 为什么**：若每页仅是一个大字符串，切片器无法可靠分辨段落、标题、页眉与跨页关系。先保留行、段落、标题、坐标和页码后，案例、法规和合同策略可以反复调整，而无需每次重新解析 PDF。
- **易错点 / 坑**：不要在规范化阶段把所有标题强行绑定为某一种文书语义；未知标题也应保留为通用 heading，语义解释可留给切片阶段。
- **延伸**：
  - 通用中间表示可作为后续知识库管理界面的文档详情数据源 ✅
- **标签**：#normalization #chunking #separation-of-concerns
- **状态**：#待复习
- **日期**：2026-09-12

### PDF 从视觉行还原为段落

- **来源问题**：单行而不是段落会有什么影响，怎样避免逻辑段落被拆成许多 block？
- **结论**：PDF 解析应按坐标还原阅读顺序行，并根据实际行距、缩进和版面特征合并为段落，而不是用固定行距阈值将每一行作为一个段落。
- **原理 / 为什么**：PDF 文本项是绘制指令，不天然携带段落语义。以页面中位行距和字高作为动态基线，可将换行的连续正文合并，同时保留真正的视觉段落间隔。
- **易错点 / 坑**：把单行当段落会造成来源定位过碎、标题误判、异常截断误报，并使跨页连续正文难以追踪。
- **延伸**：
  - 双栏、表格和扫描 OCR PDF 需要按真实样本继续校准版面重建规则 ⚠️需查证
- **标签**：#pdf #layout-analysis #paragraph
- **状态**：#待复习
- **日期**：2026-09-12

### 三层标题识别与未知栏目边界

- **来源问题**：案例栏目不可能全部写入字典；遇到未见过但版面清晰的标题，如何决定是否切片？
- **结论**：采用“通用版面评分 → 通用标题边界 → 已知栏目语义增强”的三层机制；字典不是切片的唯一依据。
- **原理 / 为什么**：短文本、非句末、上下留白、宽度、居中、字号和编号等共同给出标题置信度。高置信度未知标题也输出为 heading 并形成切片边界；已知“裁判要旨”“关联索引”等只额外映射为更精确的语义角色。
- **易错点 / 坑**：日期、数字尾行和正文换行的短句容易伪装成标题，需降低其评分，不能仅凭“文本短”判断。
- **延伸**：
  - 可对低置信度标题候选引入人工复核或本地模型二次判定 ⚠️需查证
- **标签**：#heading-detection #layout-analysis #case-law
- **状态**：#待复习
- **日期**：2026-09-12

### 案例结构的语义切片

- **来源问题**：裁判要旨、关联索引、关键词是否有必要独立切片，为什么它们被并入裁判理由？
- **结论**：裁判要旨应独立切片；关联索引宜独立为引用索引；关键词、案号和标题可形成案例摘要。此前它们未被列为案例结构节点，故被并入前一个已识别结构单元。
- **原理 / 为什么**：案例检索既需要事实和裁判理由，也常直接查询裁判规则、适用法条或关联案号。将要旨、理由和引用索引混合会降低检索命中后的可读性与引用精度。
- **易错点 / 坑**：语义栏目字典应只提供 `holding`、`case_index` 等标签增强；未知但高置信度标题仍须独立切片。
- **延伸**：
  - 后续可为不同语义角色设置检索权重，例如优先召回裁判要旨 ✅
- **标签**：#case-law #legal-retrieval #semantic-chunking
- **状态**：#待复习
- **日期**：2026-09-12

### 批量导入中的文书类别判断

- **来源问题**：批量导入不同类别文档时如何识别类别，现有规则是否对所有类型通用？
- **结论**：当前导入类别主要由 `--category` 人工指定；切片阶段可按类别和文本做基础推断，但尚未形成导入时自动分类并持久化的完整流程。
- **原理 / 为什么**：规范化层的格式处理大多通用；结构识别和切片策略则针对法规、案例、合同和通用文本不同。批量导入应在规范化后结合文件名、目录、标题、正文结构和置信度写入类别，低置信度交由人工确认。
- **易错点 / 坑**：将指导案例导入为“合同”会优先触发合同切片策略，即使正文含案例栏目；类别修正后需重新规范化并重新切片。
- **延伸**：
  - 可将类别推断结果与置信度写入规范化元数据，供知识库管理界面复核 ⚠️需查证
- **标签**：#document-classification #batch-import #chunking-strategy
- **状态**：#待复习
