# M0-M8 阶段规则

只应用当前阶段对应的小节，并结合仓库现状修正，不机械复制清单。

## M0：基线与接口契约

- 盘点全部 Next.js API Route、方法、认证、请求与响应。
- 覆盖成功、参数错误、401、404、429、500、非 JSON 和数据库不可用。
- 固定 SSE 的 `token`、`error`、`done` 及中断行为。
- 建立可同时指向 Next.js 与 Express 的契约测试。
- 不重构业务，不改变现有接口行为。

## M1：框架无关业务层

- 从 Route Handler 分离校验、业务规则、Prisma 查询和 HTTP 映射。
- Service 使用领域类型，不接收或返回框架 Request/Response。
- 领域错误与 HTTP 状态映射分离。
- 新旧入口复用同一 Service，迁移后证明外部行为不变。

## M2：Express 基础服务

- 建立应用工厂与启动入口，使测试不监听真实端口。
- 增加配置校验、请求体上限、请求 ID、结构化日志、404 和统一错误处理。
- 存活检查不依赖数据库；就绪检查反映关键依赖。
- 处理启动失败、异步错误和优雅关闭。
- 明确开发端口、代理和环境变量，不提前切生产流量。

## M3：会话和消息 CRUD

- 按查询、创建、更新、删除的依赖顺序迁移。
- 所有资源访问同时校验资源 ID 与当前用户。
- 保持分页、排序、错误文案和响应结构兼容。
- 评估事务和写接口幂等；重复幂等键不得重复写入。
- 新旧实现运行相同契约测试，回滚窗口前保留旧路由。

## M4：聊天 SSE

- 保持 SSE 事件协议，不把内部异常堆栈发给客户端。
- 响应前错误用 JSON；响应开始后的错误用 SSE `error`。
- 客户端断开时中止 AI 上游和无用工作。
- 检查代理缓冲、长连接超时、心跳和优雅关闭。
- 增加单用户并发流上限、上游超时和可观测性。
- 验证停止、半截回复、上游失败和断网场景。

## M5：前端切换与灰度

- 优先保持同源 `/api`，减少 Cookie 和 CORS 变化。
- 明确各环境代理规则和快速回退开关。
- 验证 401 跳转、错误提示、请求取消和 SSE 解析。
- 对比新旧接口错误率、延迟和数据结果。

## M6：认证迁移

- 先决定保留 Auth.js 还是迁入 Express，不默认更换认证库。
- 覆盖密码登录、注册、退出、Session、OAuth 和账号绑定。
- 设计 Cookie、CSRF、密钥、回调、Session 失效和认证限流。
- 不信任浏览器身份头；内部身份必须可验证且短时有效。
- 必须有独立设计确认、安全测试和回滚方案。

## M7：生产化与压测

- 用 Redis 或网关实现共享限流，覆盖用户、IP 和全局。
- 配置数据库连接池、等待超时和慢查询监控。
- 为 AI 上游设置超时、有限重试、熔断和并发隔离。
- 建立日志、指标、告警、存活和就绪检查。
- 同时压测短请求和 SSE 长连接，给出容量和拒绝策略。
- 验证 Docker、代理、CI/CD、部署和回滚。

## M8：全量切流与清理

- 切流前确认测试、监控、回滚和数据库兼容性。
- 设定观察窗口与量化回滚阈值。
- 确认无流量后再删除旧 Route 和过渡代码。
- 删除前搜索调用方、测试和文档引用。
- 更新架构、开发、部署和故障处理文档。
